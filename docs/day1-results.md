## Decisions taken
- Bedrock OpenAI endpoint is usable for all five candidate models with tool calling; keep the Task 3 `ROLES` on Bedrock, LiteLLM `claude-sonnet-4.6` is available for the stronger roles.
- LiteLLM `/key/info` reports spend and a 20.0 / 30d budget, so it can cross-check `SpendLedger`; `SpendLedger` stays the primary budget source (`model_spend` is empty).
- Any OpenCode run under Bladerunner uses `tool_env()` so `sh` is on PATH, otherwise Entire records no checkpoint.
- Trace tag writes use PATCH with `expectedRevision` and send the full desired tag list (replace semantics).
- Service-account feedback is 403, so trace feedback must go through the CLI with OAuth. The user's OAuth token currently lacks `observability:write` (`OAUTH_SCOPE_REQUIRED`); a re-login with that scope is pending user approval. Plan for `--no-cli-feedback` until that is done.
- Conditional detections stay OFF (Task 15 default): the flat `conditions` form is accepted, but neither it nor the regex detection produced a single hit in about 14 minutes on finalized traces. Do not design the watchdog to depend on neatlogs detection hits; recheck once if neatlogs staff explain how custom detections are evaluated.
- Do not design around `brain_remember`; it does not exist. Use `brain_query` / `brain_brief` for reads and `brain_ingest_traces` for loading trace files.
- Finalization stalled about 16:17Z to about 17:45Z and then recovered (stalled traces finalized retroactively with no data loss; new traces finalize in under about 3 minutes). Span-reading code must treat `409 TRACE_PROCESSING` as retryable, key off `finalizationStatus`, and tolerate hours of lag.
- Shelling out to the neatlogs Node CLI must strip the venv Scripts dir from PATH.

- Read `target_host` and tool args from the TOOL span input, not from span attributes: REST returns no custom attributes. Use `raw-spans` (`input.preview`, 25 per page, may be truncated, check `input.truncated`) or `.../payload?fields=input,output` (full value; `fields` is required). Pass `target_host` as an argument of the decorated tool function so it lands in the input JSON.
- Span listing keys are `spanName` and `spanType`, not `name`/`kind`; the Task 4 client models must use them.
- Detection hit cursor handling: hit order is unverified (no hits). Implement cursor pagination to exhaustion (`data.page.nextCursor`) and de-duplicate by hit id rather than relying on a page-1 scan being newest-first.
- The `.env` `NEATLOGS_INGEST_KEY` is rejected with 401 "Invalid API key" as of 18:06Z (it worked at 17:49Z). The user must supply a fresh ingest key before any further SDK export, MCP or detection-emit probe can run; REST reads with `NEATLOGS_TOKEN` still work.
